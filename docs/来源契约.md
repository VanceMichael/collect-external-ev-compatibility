# 资料提供方的格式

`/supplier/releases.html` 行给组件、版本标签、构建、配对用途、包号。`/supplier/withdraw.json` 精确到包、车系和模式，at 是供应方发布撤回声明的值班分钟，不追溯覆盖之前形成的台架记录。`/bench/boots.csv` 是开机/刷入记录，boot 是同一启动上下文，mode 是测试用途，power 是台架供电条件。`/bench/blocks.json` 行给开机、测试项、签认的构建以及结果；同一个 boot 下所需项目齐备才可判断该次组合，跨 boot 的项目不可合并。
`/dispatch/requests.json` 为待复测车系、实体终端及组合条件。 `/dispatch/stands.json` 是工位条件与现有领用，具体分钟仅为演练时钟。
`/bench/follow-up.json` 是后来取得的一次独立补测，boot 内完整的所需项目仍受原来的撤回与适用范围约束。dispatch 把工作单与新开机证据相连，并以 observed_at 记录现场回传分钟。
开机记录最后一列 paired 是台架实际配对件，power 是供电条件。复测请求的 configuration 提供申请编号对应的配对件、固件构建、模式和供电条件。`/dispatch/stands.json` 的设备与时段记录决定目前可承接的组合；accepted 表示外厂已接单但不表示已经取得合格的复测证据。补测开机记录沿用台架字段顺序。
